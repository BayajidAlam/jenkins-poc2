# Jenkins POC - CI/CD with Always-On Docker Compose Agents → Docker Hub

Jenkins pipeline builds a static nginx site and pushes the image to Docker Hub. Controller + both agents run as persistent services in `docker-compose.yml` (no per-stage container spin-up). Every build gets a unique tag: `<branch>-<environment>-<YYYYMMDD>-<short-sha>` (e.g. `main-dev-20260825-843b924`).

## Components
- `jenkins-controller` - UI + JNLP listener
- `jenkins-agent-build` - label `build`, runs Checkout + Build, has docker CLI + `/var/run/docker.sock` (DooD)
- `jenkins-agent-push` - label `push`, runs Push, has docker CLI + `/var/run/docker.sock`

Two agents are used for credential isolation (`dockerhub-creds` stays only on the push agent) and to avoid stale `docker login` state or spin-up cost.

## 1. Build the custom agent image first

Upstream `jenkins/inbound-agent:latest-jdk17` has no docker CLI. Build this before `docker compose up`, or agents register but fail every job:

```bash
docker build -f Dockerfile.agent -t jenkins-agent-with-docker:latest-jdk17 .
docker images | grep jenkins-agent-with-docker
```

## 2. Secrets cheat-sheet

| # | Secret | Where to get it |
|---|---|---|
| 1 | Admin password | `docker exec jenkins-controller cat /var/jenkins_home/secrets/initialAdminPassword` |
| 2 | `JENKINS_AGENT_BUILD_SECRET` | Manage Jenkins → Nodes → agent-build → launch command (`-secret <64-hex>`), or `http://<host>:8080/computer/agent-build/slave-agent.jnlp` |
| 3 | `JENKINS_AGENT_PUSH_SECRET` | Same as above, on `agent-push` node |

These are per-installation - wiping `jenkins_home` (`docker compose down -v`) or recreating a node re-issues them.

Git creds (`github-pat`) and Docker Hub creds (`dockerhub-creds`) are added later via UI (§8), not in `.env`.

## 3. Bring the stack up

`${VAR:?...}` in compose blocks startup until `.env` has non-empty secrets, but real secrets require the controller to be up first. Use placeholders to break the deadlock:

```bash
cat > .env <<'EOF'
JENKINS_AGENT_BUILD_SECRET=phase-a-placeholder
JENKINS_AGENT_PUSH_SECRET=phase-a-placeholder
EOF

docker compose up -d
docker ps --format 'table {{.Names}}\t{{.Status}}\t{{.Ports}}'
```

Expect all three containers up; the two agents will fail their JNLP handshake until §5 - that's expected, leave them running.

Verify host docker socket access:

```bash
docker exec jenkins-controller docker version --format '{{.Server.Version}}'
```

If "permission denied":

```bash
sudo chmod 666 /var/run/docker.sock
docker compose restart jenkins
```

## 4. First-boot Jenkins setup (UI)

Get admin password:

```bash
docker exec jenkins-controller cat /var/jenkins_home/secrets/initialAdminPassword
```

At `http://<host>:8080`, paste it, then:

1. Install suggested plugins.
2. Manage Jenkins → Plugins → Available → install **Git Parameter** → restart Jenkins (needed for the `BRANCH` dropdown).
3. Create admin user.

> Persistent JNLP agents are used, so the Docker Pipeline plugin is NOT required.

## 5. Register the two persistent agents

JNLP secrets are generated by Jenkins per node, so create the nodes first, then paste secrets into `.env`.

### Create `agent-build`

Manage Jenkins → Nodes → **New Node**:

| Field | Value |
|---|---|
| Node name | `agent-build` |
| Type | Permanent Agent |

Click Create, then configure:

| Section | Field | Value |
|---|---|---|
| General | # of executors | `2` |
| General | Remote root directory | `/home/jenkins/agent` |
| General | Labels | `build docker` |
| General | Usage | Use this node as much as possible |
| General | Launch method | Launch agents via JNLP |
| General | Availability | Keep this agent online as much as possible |
| JNLP | Tunnel / JVM options | leave blank |

Save. On the node's landing page, find the launch command:

```
curl -sO http://<host>:8080/jnlpJars/agent.jar
java -jar agent.jar -url http://<host>:8080/ -secret 9f3c8a1b2c3d4e5f67890a1b2c3d4e5f67890a1b2c3d4e5f67890a1b2c3d4e5f -name "agent-build" -webSocket -workDir "/home/jenkins/agent"
```

Copy the 64-hex string after `-secret ` → this is `JENKINS_AGENT_BUILD_SECRET`.

### Create `agent-push`

Repeat the same steps with:

| Field | Value |
|---|---|
| Node name | `agent-push` |
| Labels | `push docker` |

Copy its secret → `JENKINS_AGENT_PUSH_SECRET`.

### Retrieving a secret later

Via JNLP descriptor (curl, no UI needed):

```bash
curl -s -u admin:<admin-password> \
  http://<host>:8080/computer/agent-build/slave-agent.jnlp \
  | grep -oE '<argument>[a-f0-9]{64}</argument>' | head -1
```

(Same URL pattern works for `agent-push`.) If the hex looks truncated in a browser view, use `curl` - it's canonical.

### Put secrets in `.env`, restart

```bash
JENKINS_AGENT_BUILD_SECRET=9f3c8a1b2c3d4e5f67890a1b2c3d4e5f67890a1b2c3d4e5f67890a1b2c3d4e5f
JENKINS_AGENT_PUSH_SECRET=abcdef0123456789abcdef0123456789abcdef0123456789abcdef0123456789
```

```bash
docker compose up -d
```

Both agents should show **online** under Manage Jenkins → Nodes within ~30s. If offline, re-copy the secret (§5).

## 6. Add credentials

Manage Jenkins → Credentials → (global) → Add Credentials. **Use the UI**, not scripts (scripted values can bake in ANSI escapes and break Docker Hub auth later).

| Credential ID | Kind | Username | Password | Required when |
|---|---|---|---|---|
| `github-pat` | Username with password | GitHub user | GitHub PAT (`repo` scope) | repo is private |
| `dockerhub-creds` | Username with password | Docker Hub user | Docker Hub PAT | always |

## 7. Create the pipeline job

Dashboard → New Item → name `app-build-push` → type Pipeline → OK.

- Do **not** check "This project is parameterized" (Jenkinsfile declares its own params).
- Pipeline section:
  - Definition: Pipeline script from SCM
  - SCM: Git
  - Repository URL: `https://github.com/BayajidAlam/jenkins-poc2.git` (or your fork)
  - Credentials: `github-pat` (if private)
  - Branch: `*/main`
  - Script Path: `Jenkinsfile`
- Save.

Defaults: `DOCKER_IMAGE=bayajidph/jenkins-poc`, `GIT_REPO=https://github.com/BayajidAlam/jenkins-poc2.git` - override via file edit or build parameters.

## 8. First-build gotchas

**Script Approval** - first build fails with:

```
org.jenkinsci.plugins.scriptsecurity.scripts.UnapprovedUsageException: script not yet approved for use
```

Fix: Manage Jenkins → In-process Script Approval → Approve each pending hash → rebuild.

**Slow first build** - pulls `nginx:alpine`; later builds hit cache and finish fast.

## 9. Run the pipeline

Build with Parameters:

| Parameter | Type | Default |
|---|---|---|
| `BRANCH` | Git Parameter | `NONE` - must select a branch each build |
| `ENVIRONMENT` | Choice (`dev`/`staging`/`prod`) | `dev` |
| `DOCKER_IMAGE` | String | `bayajidph/jenkins-poc` |
| `GIT_REPO` | String | `https://github.com/BayajidAlam/jenkins-poc2.git` |

Each stage routes to its persistent agent - no container start/stop:

```
[Pipeline] node (agent-build)
... Checkout stage ...
... Build stage ...
[Pipeline] node (agent-push)
... Push stage ...
Finished: SUCCESS
```

### Verify the image

```bash
docker pull bayajidph/jenkins-poc:main-dev-20260825-843b924
docker run --rm -d -p 8088:80 --name verify bayajidph/jenkins-poc:main-dev-20260825-843b924
curl -s http://localhost:8088 | grep image-tag
# <span class="tag" id="image-tag">main-dev-20260825-843b924</span>
docker stop verify && docker rm verify
```

## Stages summary

| Stage | Runs on | What it does |
|---|---|---|
| Checkout | `agent-build` | `git clone` at `${params.BRANCH}`, computes tag `${BRANCH}-${ENV}-${YYYYMMDD}-${short-sha}` |
| Build | `agent-build` | `docker build -t ${FULL_IMAGE} .`, substitutes IMAGE_TAG/DOCKERHUB_USER placeholders |
| Push to Docker Hub | `agent-push` | `docker login` with `dockerhub-creds`, then `docker push ${FULL_IMAGE}` |
